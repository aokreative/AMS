# Subscriptions and Legal Pages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Agencies pay monthly through Paystack (M-Pesa or card) for one of four tiers; the database enforces paid-until, member and policy limits and drops lapsed agencies to read-only; sign-up records consent to new Privacy and Terms pages.

**Architecture:** Migration 015 adds `subscription_tiers`, `subscription_payments`, `agencies.paid_until / complimentary_until / terms_accepted_at`, an `agency_access()` function, one `enforce_subscription` trigger on every agency-scoped table (with a transaction-local `ams.system_write` bypass for seeding, invites and batch jobs), limit checks in the invite RPCs, and `apply_subscription_payment` for the webhook. Four Deno Edge Functions hold the Paystack secret: initialize, webhook, verify, reminders. The React app gets a Billing tab in Settings, a payment-return page, a global banner, legal pages and a consent checkbox.

**Tech Stack:** Supabase Postgres 17 (RLS, plpgsql, pg_cron, pg_net, Vault), Supabase Edge Functions (Deno), Paystack REST API, Resend HTTP API, React 19 + Vite + wouter + React Query + supabase-js + shadcn/ui, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-14-subscriptions-design.md`

## Review Focus

1. **Paystack delivers `charge.success` twice, or verify runs after the webhook** — `paid_until` moves once. Test in Task 1 (call `apply_subscription_payment` twice).
2. **Owner pays while still active** — extends from `paid_until`, not from today; paying while lapsed extends from today. Test in Task 1.
3. **Owner picks a lower tier than current usage (members or policies)** — refused before Paystack is called with the exact message. Test in Task 2 (helper) and Task 1 (`subscription_check_tier`).
4. **A non-owner, or a user of another agency, calls initialize/verify** — 403, no payment row. Test in Task 2 (helper `assertOwner`) and Task 1 (RLS on `subscription_payments`).
5. **Webhook with a bad signature or an unknown reference** — 401 / 200-and-ignored, nothing changes. Test in Task 2 (`verifySignature`) and Task 1 (unknown reference raises nothing, returns false).
